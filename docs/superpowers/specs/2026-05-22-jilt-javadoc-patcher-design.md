# Design: JILT Javadoc Patcher

**Date:** 2026-05-22  
**Branch:** feature/jilt  
**Status:** approved

## Problem

JILT generates separate `.java` builder files in `target/generated-sources/annotations/`.
These files are included in the Javadoc sourcepath but have documentation gaps:

- No class-level Javadoc on `XxxBuilder` classes or `XxxBuilders` interfaces
- No Javadoc on `build()` methods or factory methods
- Setter methods have `@return` tags copied verbatim from source fields — semantically wrong in a setter context (field return ≠ setter return)
- No `@param` tags on setter methods

## Decisions

| # | Question | Decision |
|---|---|---|
| 1 | Maven phase | New gmavenplus execution in `process-classes` (after compile, JILT files exist) |
| 2 | Script architecture | New dedicated `jilt-javadoc-patcher.groovy` — no changes to existing scripts |
| 3 | Setter transformation | Option C: keep field text as `@param` body, remove wrong `@return`, add correct `@return` |

## Pipeline Change

New execution block in the `javadoc` Maven profile, bound to `process-classes` phase:

```xml
<execution>
  <id>patch-jilt-javadoc</id>
  <phase>process-classes</phase>
  <goals><goal>execute</goal></goals>
  <configuration>
    <scripts>
      <script>${project.basedir}/scripts/javadoc-utils.groovy</script>
      <script>${project.basedir}/scripts/jilt-javadoc-patcher.groovy</script>
    </scripts>
  </configuration>
</execution>
```

Script operates in-place on `target/generated-sources/annotations/`.

## Script Architecture

**File:** `scripts/jilt-javadoc-patcher.groovy`  
**Trait:** implements `JavadocUtils` (reuses existing utility)  
**Entry point:** walks `target/generated-sources/annotations/` recursively, patches any `.java` file containing `@Generated("Jilt-` or `@JiltGenerated`.

### File Types and Patches

| Pattern | Type | Patches applied |
|---|---|---|
| `XxxBuilder.java` — no `implements XxxBuilders.*` | CLASSIC builder class | Class Javadoc, factory, setters, `build()` |
| `XxxBuilder.java` — `implements XxxBuilders.*` | STAGED builder class | Same as CLASSIC + stage-aware `@return` on setters |
| `XxxBuilders.java` | Staged interface container | Top-level interface Javadoc + each nested interface |

**CLASSIC vs STAGED detection:** presence of `implements XxxBuilders` in class declaration.

### Setter Transformation (option C)

For each setter method with existing Javadoc:

1. Extract body text from existing Javadoc (description lines, excluding `@return`)
2. Remove the `@return` tag (copied verbatim from source field — wrong here)
3. Inject `@param fieldName <extracted body text>`
4. Inject `@return this builder` (CLASSIC) or `@return {@link NextStageInterface} the next builder stage` (STAGED — return type extracted from method signature)

### Javadoc Templates

**`XxxBuilder` class:**
```
Builder for {@link Xxx}.
Generated by <a href="https://github.com/skinny85/jilt">JILT</a>.
Use the {@link #xxx()} factory method to obtain an instance.
```

**Factory method `xxx()`:**
```
@return a new builder instance to construct a {@link Xxx}; never {@code null}
```

**`build()` method:**
```
Builds and returns a new {@link Xxx} instance with the values set on this builder.
@return new {@link Xxx} instance; never {@code null}
```

**`XxxBuilders` top-level interface:**
```
Staged builder interfaces for {@link Xxx}.
Each interface represents one required construction step.
```

**Each nested interface (e.g. `Driver`, `Vehicule`, `StartDate`):**
```
Builder step: set the {@code fieldName} field of {@link Xxx}.
```

## Files Affected

| File | Change |
|---|---|
| `pom.xml` | Add `process-classes` execution to gmavenplus in `javadoc` profile |
| `scripts/jilt-javadoc-patcher.groovy` | New file |
| `scripts/javadoc-utils.groovy` | No change (reused as-is) |

## Out of Scope

- Changes to existing Lombok scripts
- Patching `src/main/java` sources
- Handling JILT `@Builder(style = BuilderStyle.FUNCTIONAL)`
